## Why

当前系统已经具备日志采集/提交与审计能力，但缺少一个“主动生成日志”的操作入口。为了演示与联调，需要一个可视化平台让测试/运维/开发人员在页面上按场景填写内容并提交日志，从而驱动后续的链上写入、审计流程与告警展示。

## What Changes

- 新增“日志生成/模拟”页面：通过表单创建并提交一条日志（任务名、来源、级别、内容、采集时间等），提交后可在日志中心看到新增记录。
- 支持可重复的批量生成能力：按数量与时间间隔生成多条日志（用于压测/演示趋势图/审计队列）。
- 提供生成模板与快捷填充：常用场景（INFO/WARN/ERROR、不同来源类型）一键填充，降低手工输入成本。
- 后端补齐对应接口（如缺失）：为 Web 端提供稳定的“创建日志”与“批量生成日志”能力，复用现有 `POST /logs` 的校验与落库/写链流程。

## Capabilities

### New Capabilities
- `log-generator-ui`: 在 Web 端提供日志生成/模拟入口与交互（单条提交、批量生成、模板快捷填充、提交结果反馈）。
- `log-generation-api`: 提供日志生成相关 API（单条创建可复用现有 `POST /logs`；新增批量生成/模拟接口与校验）。

### Modified Capabilities
- `log-view`: 日志列表展示能力扩展为可在生成后即时看到新数据（字段映射/刷新策略/状态展示一致性）。

## Impact

- 前端：`apps/web` 增加新页面与路由入口；复用现有 `dataService`/`httpClient`，新增提交日志与批量生成调用；可能需要新增表单组件与状态提示。
- 后端：`apps/server` 可能新增生成接口（例如 `POST /logs/generate`）与服务层逻辑；复用 `validateLogSubmitPayload` 与 `persistLogAndWriteChain`。
- 共享包：如需新增来源类型/字段枚举或批量生成 payload 校验，更新 `@graduation-project/shared`。
- 测试：新增接口测试/前端交互测试（最少覆盖创建成功与校验失败）。
