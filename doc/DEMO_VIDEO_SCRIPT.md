> 基于区块链的可信任务日志审计系统

---

## 第一部分：开场介绍（约 40 秒）

**【画面：系统总览页 Dashboard】**

> 卢老师好，我的毕业设计题目是"基于区块链的可信任务日志审计系统"。
>
> 在传统的运维和任务管理场景中，日志是追踪任务执行情况的重要依据。但传统日志系统存在一个核心问题：**日志存储在数据库中，数据库管理员或攻击者可以直接篡改日志内容，事后无法证明日志是否被修改过。**
>
> 我的系统就是为了解决这个问题。核心思路是：**利用区块链的不可篡改性，在日志写入数据库的同时，将日志的哈希摘要存证到区块链上。** 审计时，重新计算日志哈希并与链上记录比对，如果不一致，就说明日志被篡改了。

---

## 第二部分：系统架构简述（约 50 秒）

**【画面：仍在 Dashboard 页面，手动指向页面上的关键信息】**

> 简单介绍一下系统架构。整个系统采用前后端分离的全栈架构，分为五个核心模块：
>
> - **Agent 采集端**：负责监听本地日志文件变化，增量采集日志内容，通过 HTTP 接口提交到后端。
> - **后端服务**：基于 Node.js + Express + TypeScript 开发，使用 SQLite 存储日志原文，同时调用智能合约将日志哈希写入链上。
> - **智能合约**：名为 LogRegistry，部署在以太坊本地链上，使用 OpenZeppelin 的 AccessControl 做权限控制，负责存证日志哈希。
> - **审计引擎**：读取日志原文，重新计算 SHA-256 哈希，与数据库记录和链上存证进行三方比对，不一致则自动生成异常告警。
> - **前端平台**：基于 React 19 + Ant Design 5 开发，提供系统总览、日志中心、审计中心、异常告警、日志生成器五个功能页面。
>
> 整条数据流就是：**日志文件 → Agent 采集 → 后端接收 → SQLite 存储 + 链上哈希存证 → 审计比对 → 异常告警 → 前端可视化展示。**

## 第五部分：功能演示 — 篡改检测实验（约 60 秒）

**【操作：点击侧边栏"系统总览"，回到 Dashboard】**

> 接下来是整个系统最关键的功能演示——**篡改检测实验**。这也是我毕设的核心创新点。

**【操作：滚动到"篡改检测实验"卡片区域】**

> 篡改检测实验会自动完成 4 个步骤：
> 1. 创建一条日志并上链存证
> 2. 直接篡改数据库中的日志内容
> 3. 审计引擎重新计算哈希并与链上比对
> 4. 检测到不一致，自动生成异常告警

**【操作：点击"执行篡改实验"按钮，等待结果】**

> 实验完成了。可以看到步骤条显示：日志已创建、哈希已上链、数据库内容已被篡改、最后审计比对的结果是"失败"——因为篡改后的日志重新计算的哈希与链上存证不匹配了。系统自动生成了异常告警。
>
> **这就证明了：即使有人篡改了数据库中的日志原文，由于链上的哈希无法被修改，审计引擎一定能检测出来。这就是区块链在本系统中的核心价值。**

## 第七部分：创新点与总结（约 40 秒）

**【画面：回到系统总览页，展示完整的 Dashboard 数据】**

> 最后总结一下我的毕设的创新点：
>
> **第一，全链路闭环设计。** 从日志采集、链下存储、链上存证、审计比对到异常告警，五个环节打通为一条完整的可信链路。
>
> **第二，链上哈希存证机制。** 不直接上链保存日志原文（避免存储成本和隐私问题），而是只存哈希摘要，在保证高效的同时实现可验证性。
>
> **第三，自动化篡改检测。** 审计引擎自动完成重算哈希 → 三方比对 → 异常告警的全流程，无需人工干预。
>
> **第四，可视化展示与实验验证。** 提供了完整的前端可视化平台和一键篡改实验功能，直观地证明系统的检测能力。
>
> 以上就是我的毕设——"基于区块链的可信任务日志审计系统"的完整演示，谢谢大家。
