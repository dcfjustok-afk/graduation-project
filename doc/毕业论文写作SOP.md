# 毕业论文 AI 原子化写作 SOP

本 SOP 用于将毕业论文写作拆分为细粒度 AI 写作任务。每次只生成一个小节，生成后先人工检查技术事实，再进入下一步，避免错误在后续章节中扩散。

本文档对应的最终目录来源为 `doc/毕业论文最终目录.md`，论文题目为《基于区块链的可信任务日志审计系统设计与实现》。

## 1. 使用说明

推荐不要按目录从第 1 章直接写到第 6 章，而是按“先核心、再支撑、最后摘要与润色”的顺序完成：

1. 先准备“论文事实资料包”和统一写作规范。
2. 先写第 3 章，因为第 3 章是导师强调的核心创新点。
3. 再写第 4 章，用系统需求与总体设计支撑第 3 章。
4. 再写第 5 章，把代码实现、测试、实验数据落到论文里。
5. 再写第 2 章，让相关技术服务于前面已经写清楚的系统机制。
6. 再写第 1 章和第 6 章，因为绪论、总结要反向概括全文。
7. 最后写摘要、Abstract、关键词、参考文献整理和全文一致性检查。

每次问 AI 时都使用“公共提示词前缀 + 当前小节提示词”。这样可以保证每个小节既原子化，又不会互相矛盾。

```text
你是本科软件工程毕业论文写作助手。我的论文题目是《基于区块链的可信任务日志审计系统设计与实现》。请严格按照中国本科毕业论文写作风格撰写，语言正式、客观、连贯，避免口语化，避免夸大创新，不要使用“我”“我们”等第一人称。

论文系统事实如下：
1. 系统目标：构建一个基于区块链的可信任务日志审计系统，解决传统中心化日志容易被篡改、删除、伪造，审计结果缺少可信依据的问题。
2. 系统整体链路：日志文件 -> Agent 增量采集 -> Server 接收并写入 SQLite -> 计算 SHA-256 日志哈希 -> 写入 LogRegistry 智能合约 -> 审计阶段重新计算哈希并与数据库、链上记录比对 -> 发现异常后生成告警 -> Web 前端展示日志、审计和告警结果。
3. 系统模块：Agent 日志采集模块、Server 后端服务模块、SQLite 链下存储模块、LogRegistry 智能合约模块、审计告警模块、Web 前端可视化模块。
4. 技术栈：React、TypeScript、Ant Design、Express、Node.js、SQLite、Hardhat、Solidity、OpenZeppelin AccessControl、Ethers。
5. 智能合约：LogRegistry 合约保存 taskId、logHash、createdAt、submitter；通过 LOGGER_ROLE 控制日志写入权限；支持 storeLog、getLog、getRecordIdsByTaskId、getLogsByTaskId、getTaskLogCount、getLogCount 等能力。
6. 数据库核心表：logs、log_hash_records、audit_records、alerts、agent_states。
7. 审计机制：审计时读取日志原文重新计算 actualHash，读取数据库 expectedHash，读取链上 onChainHash，进行三方比对；一致则 passed，不一致则 failed，链上记录不可用或不完整时可 pending；failed 时生成 hash_mismatch 告警。
8. 实验结果：合约测试 8 项全部通过；日志批量提交 100 次全部成功，平均响应时间约 107.03 ms，吞吐量约 9.33 条/秒；批量审计 100/500/1000 条数据 5 轮全部成功，平均耗时约 3067.77/15659.44/35032.13 ms；篡改检测实验中系统能识别日志内容被修改并生成 failed 审计记录和告警。
9. 重要工程改进：合约代码存在性校验，避免本地链重启后空地址误判；审计时优先使用 log_hash_records.contract_address 进行历史合约地址回溯，避免多次部署后历史日志误判。
```

3. 检查实验数据是否与实验报告一致。
4. 检查第 3 章是否足够突出核心创新点。
5. 检查第 5 章是否把系统实现和实验结果写实。
6. 检查摘要、结论和正文是否互相对应。
7. 最后再进行学术语言润色和重复表达改写。

## 8. 使用注意事项

1. 不要让 AI 一次性写完整章，优先按小节生成。
2. 每个小节生成后，先人工核对技术事实，再继续下一节。
3. 国内外研究现状和参考文献部分必须后续人工核对真实文献，AI 不能编造作者、年份和文献题名。
4. 实验数据必须使用项目中已有数据，不要让 AI 自行生成新数据。
5. 第 3 章是全文重点，写作时要反复强调区块链可信存证、三方哈希比对、历史合约地址回溯和合约代码存在性校验。
6. 第 4 章负责系统需求和总体设计，不要抢写第 3 章的核心机制细节。
7. 第 5 章负责工程实现与实验验证，应多使用真实模块、真实接口和真实实验结果。
