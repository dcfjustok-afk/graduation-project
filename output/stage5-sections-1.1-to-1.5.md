# 第 1 章 绪论

## 1.1 研究背景及意义

随着信息系统在政务服务、企业管理、在线交易、自动化运维和数据处理任务中的广泛应用，系统运行过程中会持续产生大量日志数据。日志记录了任务执行过程、接口调用结果、异常错误、用户操作和系统状态变化等信息，是安全审计、故障排查、责任追溯和运行分析的重要依据。当系统发生异常或安全事件时，日志往往是定位问题来源、还原操作过程和判断责任边界的重要证据。因此，日志数据的真实性、完整性和可追溯性直接影响后续审计结论的可信程度。

传统日志管理方式多采用中心化存储模式，日志原文通常保存在服务器文件系统、数据库或集中日志平台中。这种方式具有部署简单、查询方便、与业务系统集成成本较低等优点，但在可信审计场景下也存在明显不足。首先，中心化日志存储依赖管理权限和数据库安全策略，一旦攻击者获得较高权限，可能对日志内容进行修改、删除或伪造。其次，内部人员误操作或恶意操作也可能导致关键日志缺失，使审计过程难以还原真实事件。再次，当日志原文、审计记录和校验依据都保存在同一中心化系统中时，一旦该系统被破坏，后续审计结论缺少独立可信依据。

在此背景下，如何增强日志数据的防篡改能力和审计可验证性，成为日志审计系统设计中的重要问题。区块链具有不可篡改、可追溯和交易记录公开可验证等特点，适合保存关键数据摘要和存证元数据。哈希摘要技术能够将日志原文映射为固定长度的内容指纹，日志内容一旦被修改，重新计算得到的哈希值通常会发生变化。将区块链存证与哈希校验结合，可以为链下日志提供独立校验依据，使审计过程不完全依赖中心化数据库自身的可信性。

本课题围绕“基于区块链的可信任务日志审计系统设计与实现”展开，目标是构建一个从日志采集、链下存储、链上存证、审计比对、异常告警到前端展示的完整原型系统。系统采用“链下保存日志原文、链上保存日志哈希摘要”的混合存储方式，在降低链上存储成本和保护日志内容隐私的同时，为日志完整性校验提供可信依据。审计阶段通过 expectedHash、actualHash 和 onChainHash 的三方比对，判断日志内容是否与存证时保持一致，并在发现异常时生成 hash_mismatch 告警。

本课题具有一定的理论意义和工程意义。从理论层面看，课题将区块链存证、哈希摘要和日志完整性校验结合起来，围绕可信日志审计形成较清晰的机制设计。从工程层面看，系统实现了 Agent 增量采集、Express 后端服务、SQLite 链下存储、LogRegistry 智能合约、审计告警和 React 前端展示等模块，能够验证可信日志审计闭环的可运行性。该研究可为小规模任务日志审计、教学实验和可信存证原型设计提供参考。

本节关键信息摘要：

1. 日志数据是安全审计、故障排查和责任追溯的重要依据。
2. 传统中心化日志存在被篡改、删除、伪造后缺少独立证据的问题。
3. 区块链存证与哈希校验可以为日志完整性审计提供新思路。
4. 本课题采用链下日志原文存储与链上哈希存证结合的设计。
5. 系统目标是形成日志采集、存证、审计、告警和展示的完整闭环。

## 1.2 国内外研究现状

近年来，围绕数据可信存证、日志审计和智能合约可信管理的研究不断发展。区块链存证研究主要关注如何利用链上不可篡改和可追溯特性保存关键证据，日志审计研究主要关注日志采集、集中存储、完整性校验和异常追溯，智能合约研究则为链上规则固化、权限控制和证据查询提供了可执行载体。三类研究方向相互关联，共同为可信日志审计系统提供了理论与工程基础。

已有研究通常认为，区块链适合保存数据摘要而非大规模原文，哈希函数适合用于校验链下数据是否被修改，智能合约适合将写入规则和查询接口固化在链上。这些研究为本课题采用“链下保存日志原文、链上保存日志哈希摘要”的设计提供了参考。但从工程落地角度看，现有方案仍存在一些不足，例如完整数据上链可能导致存储成本较高，日志采集过程自动化不足，链上存证、链下存储、审计比对和异常告警之间缺少完整闭环，可视化展示与告警追踪能力也有待加强。

因此，本课题在已有研究基础上，进一步面向任务日志审计场景，设计并实现包含 Agent 自动采集、Server 后端处理、SQLite 链下存储、LogRegistry 合约存证、三方哈希比对和 Web 前端展示的原型系统，重点验证可信日志审计机制在工程闭环中的可行性。

本节关键信息摘要：

1. 区块链存证、日志审计和智能合约可信管理是本课题的主要研究基础。
2. 现有研究为链上摘要存证和日志完整性校验提供了思路。
3. 相关方案仍存在存储成本、自动采集、工程闭环和可视化告警方面的不足。
4. 本课题面向任务日志审计场景，强调系统闭环实现和篡改检测验证。

### 1.2.1 区块链存证技术研究现状

区块链存证技术是区块链在数据可信证明领域的重要应用方向。相关研究表明，区块链由于具备账本共享、记录可追溯和历史数据难以篡改等特点，可以用于保存电子证据、数据摘要、交易凭证和关键操作记录。在数据完整性保护场景中，区块链常被用作外部可信记录载体，为链下数据提供时间顺序和摘要校验依据。

从存证方式看，常见方案主要包括完整数据上链和摘要数据上链两类。完整数据上链能够使数据直接成为链上记录，便于后续查询和验证，但在日志、文件、业务数据等规模较大的场景中，会带来较高的存储成本和处理开销，也可能导致敏感信息暴露。摘要数据上链则将原始数据保存在链下，只将哈希摘要、业务标识、提交时间和提交者等元数据写入链上。后续验证时，系统重新计算链下数据哈希，并与链上哈希进行比对，从而判断数据是否发生变化。

链上保存摘要、链下保存原文的模式更适合日志审计场景。日志数据通常数量较多、内容变化频繁，并且可能包含路径、错误信息、任务状态等敏感内容。如果将日志原文全部写入区块链，不仅会增加链上存储压力，还可能影响隐私保护。采用摘要上链方式，可以在保留链下查询效率的同时，为日志内容提供不可随意修改的校验依据。

但是，摘要上链模式也存在一定局限。区块链只能证明某个哈希值在某一时刻被写入链上，不能单独证明链下原文最初是否真实、采集过程是否完整。因此，可信日志审计系统还需要结合自动采集、链下数据库、权限控制和审计比对机制。本课题正是在这一思路下，将 SQLite 链下存储与 LogRegistry 链上哈希存证结合起来，形成面向任务日志的可信存证方案。

本节关键信息摘要：

1. 区块链存证常用于数据摘要、电子证据和完整性保护场景。
2. 完整数据上链可信度直观，但存在成本高和隐私风险。
3. 摘要数据上链适合日志等数量多、内容敏感的数据。
4. 摘要上链需要与日志采集、链下存储和审计比对机制结合使用。

### 1.2.2 日志审计与完整性校验研究现状

日志审计是信息系统安全管理和运行维护中的重要内容。已有研究和工程实践通常围绕日志采集、集中存储、查询分析、异常检测和审计追溯展开。通过统一收集服务器、应用程序和任务执行过程中的日志，系统可以在发生异常时定位故障原因，在发生安全事件时还原操作过程，并为责任追溯提供依据。因此，日志审计不仅关注日志是否能够被记录，还关注日志是否完整、可信和可追溯。

传统日志审计系统通常采用集中式日志平台或数据库保存日志数据。该方式便于统一检索、聚合分析和可视化展示，但在完整性保护方面仍存在不足。由于日志原文和审计依据往往保存在同一管理域内，当系统权限被滥用或数据库被攻击时，日志可能被修改、删除或伪造。若缺少独立校验机制，审计人员很难判断日志内容是否保持原始状态，审计结论的可信度也会受到影响。

在完整性校验方面，哈希摘要、数字签名、时间戳和访问控制等技术常被用于增强日志可信性。哈希摘要可以将日志内容转换为固定长度指纹，数字签名可以证明数据来源，时间戳可以辅助确定事件发生顺序。然而，如果这些校验记录仍然只保存在中心化数据库中，一旦数据库被整体篡改，校验依据也可能同时失效。因此，如何为日志校验记录提供独立可信存储，是日志完整性保护中的关键问题。

此外，传统日志审计在自动化和闭环能力方面也存在不足。一些方案重视日志集中存储和查询，但对日志采集过程中的增量读取、失败重试、审计结果写入、异常告警和前端展示关注不够。部分系统能够发现异常，但缺少与告警记录、审计记录和可视化页面的联动。本课题面向上述问题，设计 Agent 自动采集、三方哈希比对和 hash_mismatch 告警机制，以提高日志审计过程的完整性和可观察性。

本节关键信息摘要：

1. 日志审计关注日志采集、集中存储、异常检测和审计追溯。
2. 传统中心化日志系统在可信性和篡改识别方面存在不足。
3. 哈希摘要可用于完整性校验，但校验依据也需要可信保存。
4. 本课题强调自动采集、审计记录、异常告警和前端展示的闭环联动。

### 1.2.3 智能合约在可信审计中的应用现状

智能合约能够将预先定义的业务规则部署到区块链网络中，并按照合约逻辑自动执行。由于合约状态和交易记录可以在链上追溯，智能合约在可信审计场景中常用于固化写入规则、限定操作权限、保存证据摘要、提供查询接口和记录事件信息。相比仅依靠链下程序执行审计逻辑，智能合约可以为关键存证行为提供更加稳定的链上规则约束。

在数据存证与审计场景中，智能合约通常承担证据登记和查询功能。例如，系统可以通过合约方法写入数据哈希、业务标识、提交时间和提交者地址，并通过事件记录写入结果。后续审计时，链下系统可以根据业务标识查询链上记录，与本地数据库和重新计算的哈希进行比对。通过这种方式，智能合约成为链下业务数据与链上可信证据之间的连接层。

智能合约在可信审计中的优势主要体现在三个方面。第一，合约规则公开可验证，便于审计人员理解数据如何写入链上。第二，权限控制可以限制关键写入行为，避免任意地址提交伪造记录。第三，链上记录和事件具有可追溯性，便于后续定位交易和提交者。本系统中的 LogRegistry 合约即采用 AccessControl 控制 LOGGER_ROLE，只有被授权地址才能调用 storeLog 写入日志哈希。

与此同时，智能合约应用也存在一定限制。合约部署后修改成本较高，设计阶段需要谨慎确定数据结构和权限边界；链上交易存在一定性能开销，不适合承载大量日志原文；合约代码若存在安全缺陷，可能影响存证结果可信性。因此，本课题仅将日志哈希和必要元数据写入链上，并在后端加入合约代码存在性校验和历史合约地址回溯机制，以降低本地实验环境中合约地址变化带来的误判风险。

本节关键信息摘要：

1. 智能合约可用于固化写入规则、权限控制、证据查询和事件追踪。
2. 智能合约能够连接链下业务数据与链上可信证据。
3. AccessControl 可限制日志哈希写入权限，避免任意地址污染存证记录。
4. 智能合约存在性能、部署修改和合约安全方面的工程限制。

## 1.3 本文主要研究内容

本文围绕基于区块链的可信任务日志审计系统展开研究，重点面向传统中心化日志容易被篡改、删除或伪造，审计结果缺少可信依据的问题，设计并实现一个包含日志采集、链下存储、链上存证、审计比对、异常告警和前端展示的原型系统。研究过程既关注可信审计机制设计，也关注系统工程实现和实验验证之间的对应关系。本文主要研究内容包括以下几个方面。

第一，设计链上链下混合存储模型。针对日志原文数量多、内容可能敏感、直接上链成本较高的问题，系统采用链下保存日志原文、链上保存日志哈希摘要的方式。SQLite 用于保存 logs、log_hash_records、audit_records、alerts 和 agent_states 等业务数据，LogRegistry 智能合约用于保存日志哈希和任务标识等摘要证据。该模型兼顾链下查询效率、链上可信校验和日志隐私保护。

第二，设计并实现 LogRegistry 智能合约。合约保存 taskId、logHash、createdAt 和 submitter 等字段，通过 LOGGER_ROLE 控制日志哈希写入权限，并提供 storeLog、getLog、getRecordIdsByTaskId、getLogsByTaskId、getTaskLogCount 和 getLogCount 等方法。该合约为日志哈希存证和任务维度查询提供链上支撑。

第三，设计三方哈希比对审计机制。系统在日志提交阶段生成 expectedHash 并写入数据库和链上；在审计阶段重新计算日志原文得到 actualHash，并读取链上 onChainHash。通过 expectedHash、actualHash 和 onChainHash 的比对，系统将审计结果判定为 passed、failed 或 pending。当发现哈希不一致时，系统生成 hash_mismatch 类型告警。

第四，实现 Agent 自动采集与后端服务。Agent 模块支持日志文件增量读取、偏移量持久化、失败重试和状态同步；Server 后端负责日志接收、SQLite 入库、SHA-256 哈希计算、LogRegistry 合约调用、审计执行和告警生成。前端基于 React、TypeScript 和 Ant Design 展示系统总览、日志列表、审计结果和告警信息。

第五，完成系统功能测试、性能实验和篡改检测验证。实验结果表明，LogRegistry 合约测试 8 项全部通过，日志批量提交 100 次全部成功，平均响应时间约 107.03 ms，吞吐量约 9.33 条/秒；批量审计 100、500、1000 条数据 5 轮全部成功，平均耗时约 3067.77 ms、15659.44 ms、35032.13 ms；篡改检测实验能够识别日志内容被修改并生成 failed 审计记录和告警。

本节关键信息摘要：

1. 本文研究链上链下混合存储模型，以降低日志原文直接上链成本。
2. 本文设计 LogRegistry 合约，实现日志哈希存证和任务维度查询。
3. 本文提出 expectedHash、actualHash 和 onChainHash 三方比对审计机制。
4. 本文实现 Agent、Server、SQLite、智能合约和 Web 前端组成的系统闭环。
5. 本文通过功能测试、性能实验和篡改检测验证系统有效性。

## 1.4 论文组织结构

本文围绕基于区块链的可信任务日志审计系统设计与实现展开，共分为六章，各章内容安排如下。

第 1 章为绪论。本章介绍课题研究背景及意义，分析日志审计在安全审计、故障排查和责任追溯中的作用，说明传统中心化日志在可信性方面存在的不足；同时概述区块链存证、日志审计与智能合约可信管理相关研究现状，明确本文主要研究内容和论文组织结构。

第 2 章为相关理论与关键技术。本章介绍区块链与链上存证技术、智能合约与访问控制技术、哈希摘要与日志完整性校验技术，以及 React、Express、SQLite、Hardhat 等系统开发相关技术，为后续系统机制设计和工程实现提供技术基础。

第 3 章为基于区块链的可信日志存证与审计机制设计。本章是全文核心章节，重点说明链上链下混合存储模型、日志标准化封装、SHA-256 日志摘要生成、LogRegistry 合约设计、三方哈希比对、历史合约地址回溯、合约代码存在性校验以及篡改检测与异常告警机制。

第 4 章为系统需求分析与总体设计。本章从业务场景出发，分析日志自动采集、链上可信存证、审计校验、异常告警和可视化展示等功能需求，并进一步说明系统非功能需求、总体架构、功能模块、数据流、业务流程和数据库设计。
