## 2.3 哈希摘要与日志完整性校验技术

哈希摘要技术是日志完整性校验的重要基础。哈希函数能够将任意长度的输入数据映射为固定长度的摘要值，该摘要值通常以十六进制字符串形式表示。对于同一份输入数据，使用相同哈希算法得到的结果应保持一致；而当输入内容发生变化时，计算得到的摘要值也会随之变化。因此，哈希摘要可以作为数据内容的“指纹”，用于判断文件、消息或日志记录是否被修改。

安全哈希函数通常具有单向性、抗碰撞性和雪崩效应等特点。单向性是指从输入数据计算哈希值较为容易，但难以根据哈希值反推出原始输入内容。抗碰撞性是指难以找到两份不同数据，使它们计算得到相同哈希结果。雪崩效应是指输入内容即使只发生很小变化，例如增加一个字符、修改一个时间戳或删除一个空格，输出哈希值也会发生显著变化。上述特性使哈希函数适合用于完整性校验，而不是用于还原原始数据。

SHA-256 是安全哈希算法家族中的常用算法之一，其输出长度为 256 位，通常表示为固定长度的十六进制字符串。在日志完整性校验场景中，SHA-256 的作用是将日志原文转换为稳定的摘要值。系统在日志首次提交时对日志正文计算哈希，并将该哈希作为提交时的 expectedHash；后续审计时，再对当前保存的日志正文重新计算 actualHash。如果日志内容没有变化，两次计算结果应保持一致；如果日志内容被修改，actualHash 通常会与 expectedHash 不同。

在本系统中，日志进入 Server 后，后端对 log_content 字段计算 SHA-256 哈希，并生成以 0x 开头的十六进制哈希值。该哈希值一方面保存到 log_hash_records 表中，另一方面写入 LogRegistry 智能合约，形成链上存证。审计阶段，系统重新读取 logs 表中的日志原文并再次计算哈希，然后与数据库记录和链上记录进行比对。由于哈希函数对输入内容变化非常敏感，日志正文一旦被修改，即使修改幅度很小，重新计算得到的 actualHash 也会发生变化，从而暴露完整性异常。

哈希摘要技术本身并不能说明日志内容是否真实产生，也不能判断日志语义是否正确，它主要解决的是“数据是否与存证时保持一致”的问题。因此，本系统将哈希摘要与链上存证、链下数据库和审计记录结合使用。SQLite 保存日志原文和 expectedHash，LogRegistry 保存 onChainHash，审计服务重新计算 actualHash。三者共同构成完整性校验依据，使系统能够在日志内容被篡改时生成 failed 审计结果和 hash_mismatch 告警。

本节关键信息摘要：

1. 哈希函数可以将任意长度输入映射为固定长度摘要值。
2. 单向性、抗碰撞性和雪崩效应使哈希摘要适合完整性校验。
3. SHA-256 用于将 log_content 转换为日志内容指纹。
4. 日志内容一旦被修改，重新计算得到的 actualHash 会发生变化。
5. 本系统通过 expectedHash、actualHash 和 onChainHash 比对判断日志完整性。

## 2.4 系统开发相关技术

本系统除区块链、智能合约和哈希摘要技术外，还需要前端展示、后端服务、链下存储和合约开发环境共同支撑。相关开发技术并非孤立存在，而是分别服务于日志采集后的业务处理、数据保存、审计执行和结果展示。本节从 React、Express、SQLite 和 Hardhat 四个方面说明其在系统中的作用。

### 2.4.1 React 前端框架

React 是一种组件化前端开发框架，适合构建状态变化较多、页面结构可复用的 Web 应用。其核心思想是将页面拆分为多个组件，通过状态变化驱动界面更新。对于本系统而言，前端需要展示系统总览、日志中心、审计管理和告警管理等页面，不同页面中存在统计卡片、数据表格、趋势图、分布图和状态标签等可复用界面元素，因此采用 React 有助于提高页面组织的清晰度。

本系统前端结合 TypeScript 和 Ant Design 使用。TypeScript 用于约束日志记录、审计记录、告警记录和总览统计等数据结构，减少前后端字段不一致带来的问题；Ant Design 提供表格、卡片、按钮、标签和统计数值等基础组件，便于较快构建管理类界面。前端通过 API 客户端调用后端接口，将日志、审计和告警数据转换为可视化结果，从而支撑系统运行状态展示。

本节关键信息摘要：

1. React 适合构建组件化、状态驱动的前端页面。
2. 本系统前端包含总览、日志、审计和告警等页面。
3. TypeScript 约束前端数据结构，Ant Design 提供基础界面组件。

### 2.4.2 Express 后端服务框架

Express 是基于 Node.js 的轻量级 Web 服务框架，常用于构建 REST API。它提供路由、中间件和请求响应处理能力，适合实现前后端分离系统中的后端接口层。本系统需要向 Agent、Web 前端和实验脚本提供统一接口，例如日志提交、日志查询、审计触发、审计记录查询和告警查询等，因此采用 Express 作为后端服务框架。

在本系统中，Express 后端并不只是转发请求，而是承担日志入库、哈希计算、链上写入、审计比对和告警生成等业务编排职责。项目通过 routes、controllers、services、repositories、db 和 blockchain 等分层结构组织代码，使接口处理、业务逻辑、数据库访问和合约交互相互分离。该方式有助于提高后端代码的可维护性，也便于在论文实验中验证不同接口和审计分支。

本节关键信息摘要：

1. Express 用于构建系统 REST API 服务。
2. 后端接口支撑日志提交、审计触发和告警查询等功能。
3. 分层结构使接口处理、业务逻辑、数据访问和链上交互保持清晰边界。

### 2.4.3 SQLite 数据存储技术

SQLite 是一种轻量级关系型数据库，具有部署简单、无需独立数据库服务、适合本地原型系统和实验验证等特点。对于本科毕业设计系统而言，SQLite 能够在较低配置复杂度下提供结构化数据保存能力，便于保存日志、存证记录、审计记录、告警记录和 Agent 状态等信息。

本系统使用 SQLite 作为链下存储层。logs 表保存日志原文和来源信息，log_hash_records 表保存日志哈希和链上交易信息，audit_records 表保存审计结果，alerts 表保存异常告警，agent_states 表保存采集端运行状态。SQLite 的作用是支撑系统查询、展示和审计重算，而不是替代链上存证。链下数据库提供业务数据管理能力，LogRegistry 合约提供可信哈希依据，二者共同构成链上链下协同机制。

本节关键信息摘要：

1. SQLite 适合本地原型系统和实验验证场景。
2. 本系统使用 SQLite 保存 logs、log_hash_records、audit_records、alerts 和 agent_states。
3. SQLite 负责链下业务数据管理，LogRegistry 负责链上哈希存证。

### 2.4.4 Hardhat 智能合约开发环境

Hardhat 是以太坊智能合约开发和测试环境，支持 Solidity 编译、合约部署、本地链运行和自动化测试。对于需要开发 LogRegistry 合约的系统而言，Hardhat 能够提供较完整的本地开发工具，使合约编写、调试、测试和部署过程更加方便。

本系统使用 Hardhat 管理 LogRegistry 合约工程，并结合 Solidity、OpenZeppelin AccessControl 和 Ethers 完成链上存证功能。Hardhat 本地链用于实验环境中的合约部署和交易验证，测试脚本用于验证合约写入权限、日志哈希存储和任务维度查询等功能。后端通过 Ethers 连接已部署的 LogRegistry 合约，调用 storeLog 写入哈希，并在审计阶段读取链上记录。由于本地链可能重启，系统还加入合约代码存在性校验和历史合约地址回溯，以提高实验过程的可靠性。

本节关键信息摘要：

1. Hardhat 支持 Solidity 编译、部署、本地链运行和合约测试。
2. 本系统使用 Hardhat 开发和验证 LogRegistry 合约。
3. 后端通过 Ethers 与部署后的合约交互。
4. 合约代码存在性校验和历史合约地址回溯提高本地实验可靠性。

## 2.5 本章小结

本章围绕可信任务日志审计系统所涉及的相关理论与关键技术进行了说明。首先介绍了区块链与链上存证技术，明确区块链的不可篡改、可追溯和分布式账本特性能够为日志哈希提供可信存证依据。其次说明了智能合约与访问控制技术，指出 LogRegistry 合约可以通过结构化记录保存 taskId、logHash、createdAt 和 submitter，并通过 LOGGER_ROLE 限定可信写入边界。

随后，本章介绍了哈希摘要与日志完整性校验技术。SHA-256 能够将日志正文转换为固定长度摘要值，日志内容一旦被修改，重新计算得到的 actualHash 会发生变化，从而为日志篡改检测提供基础。最后，本章从 React、Express、SQLite 和 Hardhat 四个方面说明了系统开发相关技术，分别对应前端展示、后端服务、链下存储和智能合约开发环境。

综上，本章所述技术为后续系统核心机制设计提供了理论和工程基础。区块链和智能合约支撑链上可信存证，哈希摘要支撑日志完整性校验，React、Express、SQLite 与 Hardhat 则支撑系统原型的具体实现。下一章将在上述技术基础上，进一步展开基于区块链的可信日志存证与审计机制设计。

本节关键信息摘要：
