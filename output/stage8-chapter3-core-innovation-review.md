# 第 3 章核心性与区块链创新点突出程度检查报告

检查对象：`output/Graduation-thesis.docx` 第 3 章  
检查任务：判断第 3 章是否充分体现“系统核心部分”和“区块链方向创新点”，重点检查链上链下混合存储、LogRegistry 合约、三方哈希比对、历史合约地址回溯、合约代码存在性校验、篡改检测告警是否写得突出。  
检查说明：本报告只给出审稿判断和增强建议，不直接扩写论文正文。

## 一、总体判断

第 3 章已经基本承担了全文核心技术章节的作用，内容覆盖了可信日志审计系统的主要机制，包括链上链下混合存储、日志哈希生成、LogRegistry 智能合约、AccessControl 权限控制、三方哈希比对、历史合约地址回溯、合约代码存在性校验以及审计状态和告警机制。从内容完整性看，第 3 章能够体现系统区别于普通日志管理系统的关键点，即不是只做日志采集、查询和展示，而是通过区块链存证与哈希审计构建可信校验依据。

但从“突出程度”看，当前第 3 章仍有进一步增强空间。主要问题不是缺少内容，而是部分核心机制被写成了普通模块说明，章节层级和开头总述对“核心创新点”的引导不足；部分工程改进点虽然已经写到，但与可信审计准确性、实验可信性之间的关系还可以更明确；篡改检测与告警机制已经形成闭环，但在第 3 章中可以进一步强调其是三方哈希比对结果的落地环节，而不是普通告警功能。

综合判断：第 3 章“内容覆盖充分”，但“核心性表达仍可加强”。若后续按本报告建议做结构和表达统一，第 3 章可以更清楚地体现导师要求的“系统核心部分”和“区块链方向创新点”。

## 六、结论

第 3 章当前已经具备作为全文核心章节的基础，六个关键机制均已覆盖，且没有偏离系统事实。最突出的内容是链上链下混合存储模型、LogRegistry 合约设计和三方哈希比对机制；最值得继续强化的是历史合约地址回溯、合约代码存在性校验与篡改检测告警三者的“工程创新点”表达。

后续修改时不建议大幅扩写所有段落，而应优先做三类增强：第一，补齐第 3 章二级标题和章首总述，让读者明确本章是核心机制设计章；第二，在每个核心机制结尾增加一句机制意义总结，突出其对可信审计的作用；第三，将历史合约地址回溯和合约代码存在性校验归纳为链上审计可靠性增强机制，避免它们被读者理解为普通异常处理。
