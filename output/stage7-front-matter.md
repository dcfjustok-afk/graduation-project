# 摘要

随着信息系统在业务处理和自动化任务中的广泛应用，日志数据已成为安全审计、故障排查和责任追溯的重要依据。传统中心化日志存储方式虽然便于查询和管理，但日志原文及审计依据集中保存，存在被篡改、删除或伪造后难以及时发现的问题。针对上述问题，本文设计并实现了一种基于区块链的可信任务日志审计系统。系统采用“链下保存日志原文、链上保存日志哈希摘要”的混合存储模型，由 Agent 完成日志增量采集，Server 负责日志入库、SHA-256 哈希计算和 LogRegistry 智能合约调用，SQLite 保存日志、存证、审计和告警记录，Web 前端展示日志、审计和告警结果。审计阶段，系统重新计算日志原文得到 actualHash，并与数据库中的 expectedHash、链上的 onChainHash 进行三方比对；当哈希不一致时，生成 failed 审计记录和 hash_mismatch 告警。实验结果表明，LogRegistry 合约测试 8 项全部通过；日志批量提交 100 次成功率为 100%，平均响应时间约 107.03 ms，吞吐量约 9.33 条/秒；批量审计 100、500、1000 条数据 5 轮均成功；篡改检测实验能够识别日志内容被修改并生成告警。结果说明，该系统能够形成从采集、存证、审计到告警展示的可信日志审计闭环。

关键词：区块链；日志审计；智能合约；哈希校验；可信存证；异常告警

# Abstract

With the widespread use of information systems in business processing and automated tasks, log data has become an important basis for security auditing, fault diagnosis, and responsibility tracing. Traditional centralized log storage is convenient for query and management, but log contents and audit evidence are usually maintained in the same trusted domain. Once logs are tampered with, deleted, or forged, it is difficult to provide independent and reliable evidence for subsequent auditing. To address this problem, this thesis designs and implements a trusted task log auditing system based on blockchain. The system adopts a hybrid storage model in which original logs are stored off-chain and log hash digests are stored on-chain. The Agent module performs incremental log collection, the Server module handles log persistence, SHA-256 hash calculation, and interaction with the LogRegistry smart contract, SQLite stores logs, evidence records, audit records, alerts, and agent states, and the Web frontend visualizes logs, audit results, and alert information. During the audit process, the system recalculates the hash of the current log content as actualHash, reads expectedHash from the database, and obtains onChainHash from the smart contract. A three-party hash comparison is then performed to determine whether the log remains consistent with its evidence record. If an inconsistency is detected, the system generates a failed audit record and a hash_mismatch alert. Experimental results show that all eight smart contract tests passed. In the log submission experiment, 100 submissions were completed successfully with an average response time of about 107.03 ms and a throughput of about 9.33 records per second. Batch audit experiments on 100, 500, and 1000 records were completed successfully in five rounds, and the tamper detection experiment identified modified log content and generated an alert. The results indicate that the proposed system can form a trusted audit loop covering log collection, evidence storage, audit verification, alert generation, and frontend visualization.

Keywords: blockchain; log auditing; smart contract; hash verification; trusted evidence storage; anomaly alert
